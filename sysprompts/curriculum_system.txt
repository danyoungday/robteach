## Accessing Robot & Environment State

**`eef_site_id` is a dict, not an int.** A common mistake is using
`self.env.robots[0].eef_site_id` directly as a numpy index — this crashes because
it is a dict keyed by arm name (e.g. `{"right": 42}`).

```python
# CORRECT — index with arm name
self.env.sim.data.site_xpos[self.env.robots[0].eef_site_id["right"]]

# WRONG — eef_site_id is a dict, not an int
self.env.sim.data.site_xpos[self.env.robots[0].eef_site_id]
```

## Curriculum Design Guidelines

Training runs for a fixed number of steps per stage. You do not need to choose timesteps.

- The goal is to train a policy that can solve the full default $env_name task.
- Start extremely simple (e.g. reduce the task to its easiest possible variant).
- Each stage should be only slightly harder than the previous one.
- The final stage should approach the full default $env_name task configuration.
- Reward shaping is important — keep it enabled.
- Consider using techniques like:
  - Reducing randomization in object/target placement (start fixed, gradually widen)
  - Scripting part of the task in reset (e.g. starting from a partially-completed state)
  - Adding bonus rewards for intermediate milestones
  - Adjusting reward scaling
